# 架构与限制

Clerk将声明、存储、执行、查询和终端展示分别组织，源码职责见[文档导航](../README.md)。

## 一、写入边界

所有受管写入口共用本机写锁、写前检查、文件撤销日志和封存。批处理与请求应用在本地作为一组执行，未接受前失败则回滚；接受数据之后的Git提交或推送失败保留本地结果，使用[操作恢复](../maintenance/local-state.md)收尾。

永久编号登记同时考虑当前与归档资料，删除不释放已登记编号。不可变字段、创建期输入、引用和状态前置条件在执行边界校验，不以帮助中的候选提示代替约束。

## 二、已知限制

- 写锁只协调同一工作区中的Clerk写命令，不锁定编辑器或其他克隆。
- 撤销日志支持进程中断恢复，不承诺断电持久性、磁盘损坏恢复或完整文件元数据还原。
- 活动会话在同一Git公共目录下共享，不跨独立克隆传播，也不是排他锁。
- 身份取自Git配置及人员映射，不构成权限认证。本机operator只用于活动标识。
- `--as`目前仍有声明与身份解析接线不完整的问题，不依赖它覆盖有效身份。
- 上下文默认摘要正文；完整正文使用`--full`。关系与最近日志仍有数量边界。
- 文稿短名与文件身份创建后固定，修改标题不自动搬动文件或迁移全部外部链接。
- 文件引用自动修复只接受Git历史能够唯一证明且当前存在的目标，不按同名文件猜测。
- 跨克隆同时修改与合并冲突由Git处理；自动同步只进行安全快进。

## 三、验证入口

[端到端测试](../../tests/cli.rs)覆盖查询、创建权限、不可变字段、引用、状态、批处理原子性、请求重放、进程中断恢复与Git失败收尾。单元测试跟随各源码模块。

完整检查命令见[贡献说明](../../CONTRIBUTING.md)。交互分页和终端布局还需要在目标终端核对；不能用非交互输出测试替代实际按键和窗口调整检查。
